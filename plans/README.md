# Implementation Plans — Animation Family Hardening & Rebuild

Generated by `/uplift` on 2026-07-24, planned against commit `e7466a84f`
(branch `integration/all-features`). Read-only advisor pass: no source was
modified. Each plan is self-contained for a zero-context executor — read the
whole plan, honor its STOP conditions, update your row when done.

**Context.** The `integration/all-features` branch merges a family of 16 ambient
terminal animations into omp (+23,619 / −15 vs `main`). An audit of every
core-touching change confirmed the branch is **additive/cosmetic and does not
change omp's execution** — the whole workspace typechecks clean (every package
tsgo exit 0, zero `error TS`), and every core hook is a read-only getter, an
opt-in setting, or a perf win. These plans close the gap between "cosmetic by
luck" and "cosmetic by construction" (Epic A) and turn the 16-copy family into a
kit-owned contract so future changes stop being 16-file edits (Epic B).

## Dependency notes

- **004 depends on 001** — the shared session-owned host must already be fail-open
  before every widget subscribes to it; landing the boundary first means the
  consolidation can't regress crash-safety.
- **005 depends on 004** — a single shared host makes teardown one unsubscribe;
  doing the lifecycle contract before consolidation would mean redoing it.
- **006 depends on 004 (hard), 005 (soft)** — 004's cleanup deletes the 16
  duplicated `readMotionSetting()` copies, so 006's dedup becomes a verify-then-hoist
  from the kit; 006 Step 4's live-toggle reuses 005's lifecycle helper (a fallback
  is documented if 005 hasn't landed).
- **007 is independent** but touches `prompt-charge`; execute after 004 to avoid
  merge friction there.
- **Epic A ↔ Epic B**: the only hard cross-epic edge is 004→001. 002/003/008/009
  do not block Epic B and can land in any order.

## Follow-up findings (discovered during execution)

- **`MotionPolicy.#reresolve` notifies tier listeners bare**
  (`packages/animation/src/motion-policy.ts:128-130`). A throw from a tier
  listener — e.g. `AnimatedWidget.#syncToTier` calling `tui.requestComponentRender`
  (`animated-widget.ts:137-149`) — escapes to the `setSetting`/`refresh` caller and
  skips sibling policy listeners. Same bug class as plan 001, but on the
  **settings-change** path rather than the timer path, so plan 001's boundary does
  not cover it. Found by the relay judge while reviewing 001; deliberately left out
  of 001's scope fence. **Fold into plan 006** (which already owns `motion-policy.ts`):
  wrap the listener call in `#reresolve` in a per-listener try/catch mirroring
  `AnimationHost.#tick`. Severity: low.

## Findings considered and rejected

Verified during the audit and deliberately **not** turned into plans, so nobody
re-audits them:

- **`tui.ts` `lastFrameCostMs` / `renderUnderPressure` getters** — read-only,
  additive; the docstring's "strictly additive" claim holds. Not a finding.
- **`agent-session.getContextUsage()` forecast fields** — additive, guarded by
  `contextWindow > 0` + compaction enabled; base fields unchanged. Not a finding.
- **`status-line.getTokensPerSecond()`** — pure getter over a private field. Safe.
- **`context-usage.ts` WeakMap memoization** — a performance improvement (same
  outputs, fewer recomputes), not a risk. Keep.
- **`build-native.ts` `path.delimiter` change** — a correct cross-platform PATH
  fix, not animation-related and not a problem.
- **MotionPolicy forcing `off` outside a TTY / under NO_COLOR / CI / dumb term** —
  by design (the static-fallback gate). Correct fail-safe, not a bug.
- **`display.animations` defaulting to `"full"`** — not rejected; escalated to a
  decision (plan 008).
